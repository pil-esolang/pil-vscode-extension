# PIL Language for VS Code
Syntax highlighting, IntelliSense, parameter hints and symbol navigation for [PIL interpreted esoteric language](https://pil-esolang.github.io/).

## Install
Download the extension from the marketplace or download from Github releases and choose Extensions -> Install from VSIX.

VS Code 1.95 or newer is required. There's no need to install the PIL interpreter.

## PIL support
- All built-ins and constant evaluator functions with documented parameters, descriptions and links to documentation page, all language construct support
- Highlighting and completion for user constructs
- Special `call`, `func-call`, `catch` and `make` signatures
- File and workspace symbol navigation
- Basic diagnostics that cover common mistakes such as duplicate symbols or missing semicolons

```pil
const SCALE = 2, LIMIT = 100;
global score = 0;

enum Direction (East, West, North, South)
struct Vec2 (
   x,
   y,
)

# double the number
double(amount)
   local result;
   mul amount, SCALE, result;
   return result;

# main program entry point
main()
   local position, result;
   make Vec2, position, 80, 24;
   call result, double, position.x;
   println result, Direction.East;
```

## Includes and working directory
PIL resolves relative `@include` paths from the interpreter's working directory. The extension defaults to the owning workspace folder, or the containing directory of a standalone file. Match your execution setup with:
```json
{
  "pil.workingDirectory": "examples/ascii-game"
}
```

Relative settings resolve from the workspace folder; absolute directories are supported. Nested includes use the same working directory. Repeated and cyclic includes are guarded, and independent programs keep separate completion scopes.

When multiple independent entry files include the same file, an ambiguity diagnostic explains how to select a program. Set `"pil.entryFile": "path/to/main.pil"` to choose that program's context for shared includes. This path resolves from the workspace folder independently of `pil.workingDirectory`.

## Dynamic values
Field suggestions use known direct construction, simple copies and swap, and discard type assumptions after uncertain writes. Unknown receivers show owner-labelled candidate fields. Dynamic function pointers retain generic parameter hints when their target cannot be resolved statically. Constant expressions are indexed without executing your code; complex enumeration initializer expressions are displayed as written.

This extension does not implement a debugger, formatter, runtime type inference or complete compiler diagnostics.

## Development

Use Node.js 22 or newer:

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run test:integration
npm run package
```

Linux extension-host tests need a display; use `xvfb-run -a npm run test:integration` on a headless machine. Tests exercise actual VS Code providers, the latest factorial and ASCII-game examples, and all 13 shipped PIL example files.

Language data is pinned in `src/catalog/upstream.json`: interpreter `90fe7e2aa3f50eeb068ad269d0c1e11ee7e8ba80`, documentation `65c3c6e175d5759842774d0a3c2bc4d2d6c2598e`. The completed documentation supplies descriptions and parameter labels; interpreter registration metadata supplies inventory, minimum arity and variadic flags.

```sh
npm run check:builtins -- --source /path/to/PIL
python scripts/import-upstream.py /path/to/PIL /path/to/pil-esolang.github.io
```

The checker validates runtime registrations and evaluator functions. The importer regenerates the catalogs, grammar and source metadata from the supplied checkouts.
